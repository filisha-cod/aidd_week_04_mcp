2. Как подхватывается skill
----------------------------------------
Skills в .qwen/skills/<имя>/ (SKILL.md + скрипт + тесты) подгружаются
АВТОМАТИЧЕСКИ: в system-reminder начала сессии `make_report` уже был
в списке доступных skills, без единого вызова инструмента Skill.

Явного указания skill в сессии не было — работа шла по прочитанному
SKILL.md. Его блоки «Когда применять / Данные / Запуск / Проверка»
образуют контракт: источник данных, путь запуска, результат, проверка.

Разные description -> разное поведение агента:
  - Если бы description было только «генерирует Excel-отчёт по
    задачам», я бы сам разбирал ТЗ, искал данные, спрашивал про формат.
  - С содержательным description агент не переспрашивает (в этой
    сессии ask_user_question не вызывался ни разу) и не читает ТЗ
    заново — сразу идёт по зашитому в skill пути.

3. Сравнение подходов: БЕЗ skill / СО skill
----------------------------------------
Критерий                  | Без skill                                            | Со skill
--------------------------+------------------------------------------------------+---
Понимание формата         | Читать и интерпретировать report_format.txt         | SKILL.md даёт контракт: источник, запуск,
                          | (~200 строк ТЗ) с нуля                              | результат, проверка
Поиск данных              | Искать apps/, понимать структуру JSON+HMAC         | glob за 1 шаг; путь и поля заданы в SKILL.md
Построение отчёта         | Писать скрипт с нуля (openpyxl, сортировка по       | Готовый детерминированный скрипт;
                          | 4 ключам, форматы дат, пустые ячейки)               | выбор из двух вариантов реализации
Сортировка строк          | Риск: «Не выполнена» раньше «Выполнена»             | Проверена построчно (A8:J31): не выполненные
                          | (не алфавитный порядок)                             | -> ранг -> дедлайн -> id
Детерминизм               | Риск записать формулу СЕГОДНЯ(), цифры «уплывут»     | Значения статичны, дата в A2; тесты фиксируют
                          | по дням                                                   | структуру
Пустые ячейки             | Типовая ошибка — писать текст «null»/«—»            | Проверено: null в F/G — действительно пустые
                          |                                                      | ячейки, «Нет дедлайна» — текстом
Форматы чисел             | Риск перепутать % и счётчики                       | Подтверждено чтением книги (46.7; 42.9; 55.6)
Верификация               | Ручная сверка с UI/API — дорого и ненадёжно         | unittest 8/8 + пересчёт из сырого JSON +
                          |                                                      | чтение листов
Токены (/stats) и время   | Нет доступа к метрикам сессии                      | Требуется команда /stats; в отчёте помечено
